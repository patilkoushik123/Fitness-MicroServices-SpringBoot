# Fitness-MicroServices-SpringBoot

# 🏋️‍♂️ Fitness Activity Intelligence Platform

A production-ready **Spring Boot Microservices Ecosystem** designed for scalable backend performance, polyglot persistence, asynchronous event processing, and AI-driven health recommendations.

---

# 🏋️‍♂️ Fitness Activity Intelligence Platform

## 🧩 Microservices Breakdown

| Service | Primary Stack | Responsibility & Database |
| :--- | :--- | :--- |
| **🚪 API Gateway** | Spring Cloud Gateway (Reactive) | Entry point, routing, rate-limiting, dynamic routing to microservices |
| **🔍 Discovery Server** | Spring Cloud Netflix Eureka | Service registration & dynamic discovery |
| **⚙️ Config Server** | Spring Cloud Config | Centralized configuration management across all services |
| **👤 User Service** | Spring Boot, PostgreSQL | Manages user identity, profile state, and authentication rules |
| **🏃 Activity Service** | Spring Boot, MongoDB | High-throughput logging of daily workouts and fitness activities |
| **🤖 AI Service** | Spring Boot, Grok LLM API | Consumes activity streams via RabbitMQ to generate intelligent recommendations |

---

## 🗄 Polyglot Persistence Strategy

* **PostgreSQL (RDBMS):** Houses structured, transactional user data where strict relational integrity and ACID compliance are required (Profiles, Roles, Account status).
* **MongoDB (NoSQL):** Stores high-volume, dynamic, and unstructured fitness log records, providing low latency and flexible schema scaling.

---

## 🔄 End-to-End System Workflow

1. **Authentication & Ingress**
   * Requests land at the **Spring Reactive API Gateway**.
   * Security is validated against **Keycloak** using **OAuth2 Resource Server** standards and **JWT tokens**.

2. **Activity Logging (Synchronous / Ingress)**
   * User submits workout details through the Gateway to the **Activity Service**.
   * The Activity Service persists raw logs directly to **MongoDB**.

3. **Event-Driven Messaging (Asynchronous)**
   * Upon successful persistence, the **Activity Service** produces an activity event and publishes it to **RabbitMQ**.

4. **AI Intelligence & Recommendation Generation**
   * The **AI Service** listens to the RabbitMQ queue, consumes the activity payload asynchronously, and calls the external **Grok AI API**.
   * Contextual health feedback and fitness recommendations are generated by Grok AI and stored back into **MongoDB** / returned to the user feed.

---

## 🛡️ Security Architecture

* **Centralized Identity Provider:** **Keycloak** handles single sign-on (SSO), token issuing, and credential management.
* **Service Isolation:** Microservices operate as **OAuth2 Resource Servers**, validating JWT claims and enforcing **Role-Based Access Control (RBAC)** locally without touching core databases for auth checks.

---

## 🚀 Key Technical Highlights

* **Resilient Infrastructure:** Dynamic service registration using **Eureka Discovery**.
* **Asynchronous Decoupling:** Non-blocking event streams via **RabbitMQ** keep core CRUD execution fast while background AI processing runs independently.
* **Modular AI Integration:** AI capabilities remain cleanly encapsulated inside the `aiservice`, preventing external API latency from slowing down core domain services.
